# Mansur-Rig 3.0 — De licencia cerrada a distribución abierta en GitHub

## Descripción
Mansur-Rig (cubierto en este vault el 2026-05-05 en su versión con licencia) pasó en diciembre 2025 a una "estructura parcialmente open-source": el ejecutable y la librería de nodos C++ siguen siendo cerrados, pero la distribución se mueve a un repositorio público en GitHub (github.com/asaf-b/Mansur-Rig), se elimina la activación obligatoria por licencia, y el servidor de licencias original se apaga el 1 de marzo de 2026. Es de Assaf Ben Zur, ex Lead Rigging TD de MPC — un rig builder modular "One-Stop-Shop" usado en producción real.

## Fundamento matemático / técnico
Mansur-Rig se basa en una librería de nodos C++ dedicada (no documentada públicamente en detalle, pero descrita como diseñada para "easy rig setups") en lugar de depender únicamente de los nodos nativos de Maya — un enfoque distinto al 100%-nodos-nativos que sigue Laia. El valor técnico de esta actualización específica no es algorítmico sino de distribución: al pasar a GitHub Releases, el ciclo de updates/parches se vuelve auditable y versionado públicamente (tags, changelog, releases), lo cual es relevante si Laia evalúa herramientas de terceros para integrarlas o solo para comparar arquitectura de distribución de su propio autorig_tools si en algún momento lo abre a otros usuarios.

## Implementación en Maya
- Maya 2026 soportado; Linux temporalmente descontinuado en esta versión.
- Instalación ahora vía descarga directa desde GitHub Releases, sin registro ni activación online.
- Incluye librería de rigs de personajes y vehículos pre-armados, también gratuitos.
- Documentación migrada a asaf-b.github.io/mansur-docs.

## Comparación con autorig_tools
No hay solapamiento de código aprovechable (la librería de nodos es C++ cerrada), pero sí es relevante como caso de referencia de mercado: confirma que la tendencia de la industria (mGear, dpAutoRigSystem, ahora Mansur-Rig) es hacia distribución abierta/gratuita de rig builders, lo cual valida la dirección de mantener autorig_tools como sistema propio diferenciado por calidad matemática (matrix puro, ribbon de Boor, RBF) en vez de competir en feature-count con estas herramientas generalistas.

## Aplicable directamente
NO — Sin código reutilizable (núcleo cerrado en C++). Relevante solo como inteligencia de mercado/competidores, no como fuente técnica.
