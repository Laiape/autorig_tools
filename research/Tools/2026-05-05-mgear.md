# mGear 5.3 — Open-Source Modular Rigging Framework for Maya

## Descripción
mGear es el framework de rigging modular open-source más consolidado del sector para Autodesk Maya. En su versión 5.3 (abril 2026) se ha convertido en la release más completa hasta la fecha, añadiendo ocho nuevas herramientas, soporte para Maya 2027 y mejoras profundas en deformación, evaluación paralela y flujos SDK. Es el estándar de facto en estudios de producción que usan Maya.

## Stack técnico
- Language: Python 3 (custom PyMaya wrapper replacing PyMEL since v5.0)
- Platform: Autodesk Maya 2022+ (Windows, macOS, Linux; Maya 2027 added in 5.3)
- License: MIT
- Key dependencies: mGearWeightDriver (custom fork of SHAPES weightDriver), numpy
- Companion tool: ueGear for Unreal Engine 5 round-trip
- Stars: 1000+ (mgear-dev/mgear)

## Detalles técnicos

### Arquitectura
- **Shifter**: modular component system; each component is self-contained with guide objects, build logic, and data. Supports Blueprint Guides (v5.2) for shared rig settings across multiple characters with per-component overrides.
- **Component build pipeline**: JSON-based guide data; rigs fully reconstructable from data files.
- **xPlorer** (v5.2): replacement outliner with Softimage XSI-inspired design; drag-and-drop reordering.

### mGear 5.3 New Tools (April 2026)
1. **Blendshape Transfer Tool** — transfers blendshapes between meshes (handles multiple source meshes); critical for corrective shape reuse.
2. **SDK Creator** — generates Set Driven Key setups directly from timeline poses; pose-to-SDK automation.
3. **Evaluation Partition** (v5.3.2: portable via short names) — splits meshes into polygon group partitions optimised for Maya's parallel evaluation mode; significant performance gains on heavy meshes.
4. **Bookmarks tool** — saves/recalls selection bookmarks; supports namespace management across rig instances.
5. **Wire to Skinning conversion** — converts wire deformer influence to skinCluster weights.
6. **Build Log Window** — colour-coded rig build monitoring.
7. **Guide Template Manager** — thumbnail previews for guide archetypes.
8. **Matcap Viewer** — in-viewport deformation evaluation without texture overhead.

### RBF Manager
- v2.1 (mGear 5.1, Sept 2024): new solver replacing SHAPES' native weightDriver with **mGearWeightDriver** (custom fork). Old kernel retained as fallback option.
- Supports duplicate driver-pose handling and improved interpolation stability.
- Solvers drive blendshapes, joint corrections, and arbitrary attribute outputs.

### IK/FK System
- mGear 5.1 improved IK/FK matching for arbitrary FK section lengths and enhanced arm/leg matching with IK configuration support.
- Standard Shifter components: arm, leg, spine (FK/IK ribbon), neck, finger, eye, facial.

### PyMaya wrapper
- Introduced in 5.0; replaces PyMEL entirely. Lightweight layer over `maya.cmds` and `maya.OpenMaya`. Eliminates PyMEL's performance overhead and startup cost.

## Comparación con autorig_tools
mGear es sustancialmente más grande y con más comunidad que autorig_tools. Su enfoque modular con guides + JSON es similar conceptualmente, pero mGear tiene capas de abstracción más rígidas (el sistema Shifter). La ventaja de autorig_tools es el control total sobre el pipeline y la integración directa con el patrón local_mmx. El RBF Manager de mGear y el SDK Creator son herramientas que Laia podría evaluar para incorporar funcionalidad equivalente en su pipeline.

## Takeaways aplicables
- **SDK Creator** (poses → SDK automático) es un concepto que encaja directamente en el flujo de trabajo de correctivos de autorig_tools. Implementar algo similar: capturar pose actual, generar driver/driven key automáticamente.
- **Evaluation Partition** por grupos de polígonos para optimizar Maya parallel evaluation — técnica aplicable a personajes pesados.
- **Blendshape Transfer Tool** multi-source: útil cuando hay variantes de personaje con topología idéntica (ej. cuerpo base + cuerpo vestido).
- El sistema Blueprint Guides para compartir configuraciones entre personajes es un patrón arquitectural a considerar para autorig_tools (templates JSON reutilizables entre personajes de la misma familia).
- La migración de PyMEL a un wrapper propio sobre `maya.cmds`/`OpenMaya` valida la dirección que ya toma autorig_tools.
