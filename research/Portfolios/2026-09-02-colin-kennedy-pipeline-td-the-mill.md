## Cómo presenta los proyectos
El USD-Cookbook demuestra expertise de pipeline a través del código mismo, no de descripciones de proyectos. Cada sub-directorio es un proyecto autónomo que muestra cómo hacer una cosa específica con USD: añadir comentarios a USD files, usar SetKind en UsdPrim, composition arcs, customizar userProperties, edit targets, etc. La estructura del repo (Features → Concepts → Tricks → Plugins → Tools → References) es una taxonomía pedagógica: cada categoría sirve un propósito de aprendizaje distinto. Los README de cada sub-proyecto explican el concepto sin necesitar contexto del repo principal.


Este modelo comunica expertise de forma verificable directamente: cualquier pipeline TD puede clonar el repo, ejecutar un ejemplo, y evaluar si el código es correcto y útil. No requiere que el visitante confíe en la descripción del autor. El reel de 2015 (Pipeline TD Reel en Vimeo) documenta trabajo en Nuke y Maya como evidencia de producción histórica, pero no es el foco actual del portfolio.

## Lo que tiene que Laia no tiene


1. **USD/Universal Scene Description como competencia explícita del pipeline** — Colin tiene USD-Cookbook como proyecto principal y USD como skill declarada. USD es ahora el estándar de inter-operabilidad de pipeline en VFX de tier 1 (Pixar, ILM, DNEG, Framestore todos usan USD o migran hacia él) y comienza a aparecer en AAA games (Epic con Unreal/USD, Unity con OpenUSD). Laia no menciona USD en ningún punto del portfolio. Incluso una frase — "rigging pipeline compatible con exportación a USD" o "familiarizado con USD stage/layer model para integración en pipelines modernos" — señalaría a los reclutadores de estudios que han migrado o están migrando a USD que la autora conoce el ecosistema moderno.


2. **GitHub como portfolio técnico principal con historia de commits verificable** — Colin usa GitHub con 146 repos como evidencia primaria de skills. La historia de commits de un repo es verificable: muestra cuándo se trabajó, cómo evolucionó el código, y si el mantenimiento es sostenido o episódico. Laia describe 9 tools sin ningún repo público. El archivo recomienda consistentemente publicar al menos Auto Skin Transfer en GitHub desde la semana 05-06 (20+ semanas). Un repo con commits regulares durante 6+ meses — incluso con una sola tool — es evidencia técnica que no puede ser replicada con texto.


3. **Proyecto que se convierte en recurso de la comunidad (no solo en portfolio piece)** — USD-Cookbook no es un showcase del trabajo de Colin, es un recurso que otros pipeline TDs usan para aprender USD. Cuando una obra de un portfolio se convierte en referencia de la comunidad, su autor gana visibilidad permanente en búsquedas de "USD Python examples" o "how to use USD plugins" independientemente de si está buscando trabajo. Laia tiene 9 tools que describe; ninguna tiene la estructura de un recurso pensado para que otros riggers lo usen. El Auto Skin Transfer o el Skin Manager, si se publicaran en GitHub con documentación suficiente, tienen el potencial de ser buscados por riggers con el mismo problema que los motivó.
